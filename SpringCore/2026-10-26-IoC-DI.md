# Framework
코드를 구현하는 개발 시간을 줄이고, 코드의 재사용성을 중가시키기 위해 일련의 클래스 묶음이나 뼈대, **틀을 제공**하는 라이브러리를 구현해 놓은 것.

- 개발자가 따라야 하는 가이드 제공
- 개발할 수 있는 범위가 정해져 있음
- 다양한 도구, 플러그인을 지원

## 장단점

- 개발 시간을 줄일 수 있다.
- 정형화 되어 있어 일정 수준 이상의 품질을 기대할 수 잇다.
- 유지보수가 쉽다.
- 프레임워크에 지나치게 의존하면 개발자의 능력이 저하될 수 있다.
- 프레임워크 사용법 습득에 시간이 오래 소요될 수 있다.

## 종류

- 영속성 프레임워크
    - Mybatis
    - Hibernate (JPA 의 구현체)
- 자바 프레임워크
    - **Spring Framework**
    - 전자정부표준-Spring
    - Struts
- 화면 구현 프레임워크
    - Bootstrap
    - Foundation
- 기능 및 지원 프레임워크
    - Log4j
    - JUnit5

## IoC
기본 Java 프로그래밍에서는 개발자가 new 로 객체 생성을 선언하고, 객체를 만들고 생성하는 시점을 Application이 정하고 있다.  
**Inversion of Control (제어의 역전)** : **객체 생성 시점, 객체 생성 및 관리를 Spring 에서** 한다. (개념이기에 Spring 에만 있는 것은 아니다)  
**Bean** : 스프링 컨테이너가 만들어 관리하는 객체

`ApplicationContext` : new 로 ApplicationContext 에 넣는 코드는 SpringContainer 를 만드는 코드이다.
- `getBean()` : 스프링 컨테이너가 보관 중인 객체 가져오기
주로 사용되는 건 Component Scan 방식

### XML config
하나하나의 bean 정보를 xml 에 등록한다. 옛날 방식.
- `<beans>` : XML 로 Spring bean 을 만들기 위한 태그

```xml
<!-- src/main/resources/section01/xmlconfig/spring-context.xml -->

<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://www.springframework.org/schema/beans https://www.springframework.org/schema/beans/spring-beans.xsd">
    <!-- member 라는 이름으로 SpringContainer 에 보관 -->
    <bean id="member" class="com.ohgiraffers.common.MemberDTO">
        <!-- 생성할 때 필수값을 잊지 않게 하기 위해 DTO 에 기본 생성자를 만들어 놓지 않았기에 값 필수 -->
        <!-- 생성자에 넣을 값들 정의 -->
        <constructor-arg index="0" value="1"/>
        <constructor-arg name="id" value="user01"/>
        <constructor-arg index="2"><value>pass01</value></constructor-arg>
        <constructor-arg name="name"><value>홍길동</value></constructor-arg>
    </bean>
</beans>
```

```java
import com.ohgiraffers.common.MemberDTO;
import org.springframework.context.ApplicationContext;
import org.springframework.context.support.GenericXmlApplicationContext;

public class Application {

    public static void main(String[] args) {
        // Spring Container 를 만드는 코드
        // 기본적으로 resources 하위에서 찾기에 resources 하위의 경로를 입력
        ApplicationContext context = new GenericXmlApplicationContext("section01/xmlconfig/spring-context.xml");

        // bean 의 id 와 개대하는 반환타입을 함께 전달하여 가져온다
        // 이름만 전달해서 가져올 경우 타입을 확정할 수 없기에 Object 로 반환한다.
        MemberDTO member = context.getBean("member", MemberDTO.class);

        System.out.println("member = " + member);
    }
}
```

### Java config
Java 의 클래스를 XML 설정 파일처럼 사용하는 방식  
- `@Configuration`  : 일반 클래스가 아니라 Spring 설정이 담긴 클래스라는 의미의 어노테이션. 해당 어노테이션이 담긴 클래스는 스프링이 자동으로 bean 으로 만든다.  
- `@Bean` : 속성 name 에 담긴 이름을 가진 bean 을 만들도록 한다. name 속성을 명시적으로 표현하지 않으면 메소드의 이름을 bean 의 이름으로 자동으로 사용한다. **외부 라이브러리처럼 `@Component` 를 직접 붙이기 어려울 때 사용**  

```java
import com.ohgiraffers.common.MemberDTO;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

// configurationSection02 라는 이름의 bean 을 스프링이 자동으로 생성해준다.
/* 해당 클래스가 빈을 생성하는 클래스임을 표기한다 */
@Configuration("configurationSection02")
public class ContextConfiguration {

    // 스프링한테 객체 생성을 어떻게 만들지 알려줌
    /* @Bean : 해당 메소드의 반환 값을 스프링 컨테이너에 bean 으로 등록한다 */
    @Bean(name="member")
    public MemberDTO getMember() {
        return new MemberDTO(1, "user01", "pass01", "홍길동");
    }
}
```

```java
import com.ohgiraffers.common.MemberDTO;
import org.springframework.context.ApplicationContext;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;

public class Application {

    public static void main(String[] args) {
        // 설정 정보가 저정되어 있는 클래스 타입을 지정
        ApplicationContext context = new AnnotationConfigApplicationContext(ContextConfiguration.class);

        MemberDTO member = context.getBean("member", MemberDTO.class);
        System.out.println("member = " + member);
    }
}
```

### Component scan
Spring 이 자동으로 찾아서 등록하는 방식  
- `@Component` : 스프링이 관리할 후보로 넣는 어노테이션 (bean 의 이름을 따로 저장해주지 않으면 앞글자가 소문자인 클래스명으로 저장)  
    - `@Controller` `@Service` `@Repository` `@Configuration` 은 컴포넌트의 역할을 더 정확히 분리해둔 어노테이션  
- `@ComponentScan(basePackages = "패키지명")`  : 탐색을 시작할 패키지 확인  

```java
package com.ohgiraffers.common;

import org.springframework.stereotype.Component;

import java.util.HashMap;
import java.util.Map;

// 스프링이 관리할 후보에 넣는 어노테이션
@Component
/* 회원 정보를 메모리에 저장하고 조회·등록하는 수업용 DAO */
public class MemberDAO {

    private final Map<Integer, MemberDTO> memberMap;

    public MemberDAO() {
        memberMap = new HashMap<>();

        memberMap.put(1, new MemberDTO(1, "user01", "pass01", "홍길동"));
        memberMap.put(2, new MemberDTO(2, "user02", "pass02", "유관순"));
    }
}
```

```java
package com.ohgiraffers.section03.annotationconfig;

import org.springframework.context.annotation.ComponentScan;
import org.springframework.context.annotation.Configuration;

/* ComponentScan : basePackages 로 설정된 하위경로에 특정 어노테이션(@Component)을 가지고 있는 클래스를 bean으로 등록한다.
* 목적에 따라 세부 기능을 제공하는 @Controller, @Service, @Repository, @Configuration 등을 사용한다. */
@Configuration
@ComponentScan(basePackages = "com.ohgiraffers.common")
public class ContextConfiguration {
}
```

```java
package com.ohgiraffers.section03.annotationconfig;

import org.springframework.context.ApplicationContext;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;

public class Application {

    public static void main(String[] args) {
        ApplicationContext context = new AnnotationConfigApplicationContext(ContextConfiguration.class);

        // 관리하는 bean 이름들을 문자열 배열로 꺼내온다.
        String[] beanNames = context.getBeanDefinitionNames();
        for(String beanName : beanNames) {
            System.out.println("beanName : " + beanName); // contextConfiguration, memberDAO, 그 외 스프릥 내부설정 bean
        }
    }
}
```

## DI
Dependency Injection (의존성 주입) : 필요한 객체를 누가 연결해 주는가  

객체 관계 (객체A가 객체B 필드에 의존)

```java
public class MemberDTO {
    private int sequence;                 //회원번호
    private String name;                  //이름
    private String phone;                 //휴대폰번호
    private String email;                 //이메일
    // **MemberDTO 가 Account 에 의존**하고 있다.
    private Account personalAccount;      //개인계좌
}
```

개발자가 직접 의존성 주입하는 방식

```java
Account account = new PersonalAccount(20, "110-234-567890");

MemberDTO member = new MemberDTO();
// 이미 외부에서 만든 객체를 필요에 의해 주입
member.setPersonalAccount(account);
```

### XML config
`<property name="sequence" value="1" />` : Setter 사용. name : 필드명, value : 값, ref : 관리하는 컨테이너에서 특정 이름의 bean 을 찾는다.

하나의 Application 클래스의 역할이 줄었다.

```xml
<!-- resources/section01/xmlconfig/spring-context.xml -->

<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://www.springframework.org/schema/beans https://www.springframework.org/schema/beans/spring-beans.xsd">

    <!-- bean 태그의 클래스 속성은 인터페이스 타입이 아닌 구현 클래스 타입으로 작성해야 한다. -->
    <bean id="account" class="com.ohgiraffers.common.PersonalAccount">
        <constructor-arg index="0" value="20"/>
        <constructor-arg index="1" value="110-234-567890"/>
    </bean>

		<!-- setter 주입 -->
    <bean id="member" class="com.ohgiraffers.common.MemberDTO">
        <!-- Setter 를 이용해서 bean 을 생성 -->
        <property name="sequence" value="1" />
        <property name="name" value="홍길동" />
        <property name="phone" value="010-1234-5678" />
        <property name="email" value="hong123@gmail.com" />
        <property name="personalAccount" ref="account" />
    </bean>
</beans>
```

```java
        ApplicationContext context = new GenericXmlApplicationContext("section01/xmlconfig/spring-context.xml");
```

### Java config

```java
import com.ohgiraffers.common.Account;
import com.ohgiraffers.common.MemberDTO;
import com.ohgiraffers.common.PersonalAccount;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class ContextConfiguration {

    @Bean
    public Account accountGenerator() {
        return new PersonalAccount(20, "110-234-567890");
    }

		// Setter 주입
    @Bean
    public MemberDTO memberGenerator() {
        MemberDTO member = new MemberDTO();
        member.setSequence(1);
        member.setName("홍길동");
        member.setPhone("010-1234-5678");
        member.setEmail("hong123@gmail.com");
        member.setPersonalAccount(accountGenerator());

        return member;
    }
}
```

```java
import com.ohgiraffers.common.MemberDTO;
import org.springframework.context.ApplicationContext;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;

public class Application {

    public static void main(String[] args) {
        ApplicationContext context = new AnnotationConfigApplicationContext(ContextConfiguration.class);

        // MemberDTO bean 이 하나뿐이기에 타입만으로 가져올 수 있다.
        MemberDTO member = context.getBean(MemberDTO.class);

}
```

Application → Controller (요청 전달)(Service 필요) → Service (업무 처리)(Repository 필요) → Repository (데이터 저장, 조회)

**생성자 주입 : 필수적인 필드를 final 필드로 선언해두고 생성자에서 주입**

### 어노테이션 기반 DI
- `@Repository` : `@Component` 의 세분화 어노테이션의 한 종류로 DAO 타입의 객체에 사용. DAO 계층의 인터페이스를 구현하는 클래스는 Impl 을 붙이는게 일반적이다.
    
    ```java
    @Repository("bookDAO")
    public class BookDAOImpl implements BookDAO { }
    ```
    
- `@Autowired` : 관리하고 있는 객체 중 해당 타입의 bean 객체를 자동으로 주입해준다.
    - 필드 주입
        - 필수적인 의존성을 알기 힘들다.
        - 단위 테스트에서 넣기 힘들다.
        
        ```java
        /* @Service : @Component의 세분화 어노테이션의 한 종류로 Service 계층에서 사용한다. */
        @Service("bookServiceField")
        public class BookService {
            /* BookDAO 타입의 빈 객체를 이 프로퍼티에 자동으로 주입해준다.
            * 의존관계에 있는 BookDAO라는 타입과 일치하는 빈이 있다면 넣어줘~ */
            @Autowired
            private BookDAO bookDAO;
        }
        ```
        
        ```java
        public class Application {
            public static void main(String[] args) {
        
                // 패키지명을 넣으면 해당 패키지 안에 들어있는 것들을 bean 으로 만든다.
                /* AnnotationConfigApplicationContext 생성자에 basePackages 문자열을 전달하며 ApplicationContext 생성한다.  */
                ApplicationContext context = new AnnotationConfigApplicationContext("com.ohgiraffers.section01");
        
                BookService bookService = context.getBean("bookServiceField", BookService.class);
            }
        }
        ```
        
    - Setter 주입
        - 주입이 일어나는 메소드가 코드에 드러난다.
        - Setter 가 불리기 전 해당 의존관계 객체가 존재하지 않을 수 있고, 생성 이후에 외부에서 접근하여 바뀔 수 있다.
        
        ```java
        /* @Service : @Component의 세분화 어노테이션의 한 종류로 Service 계층에서 사용한다. */
        @Service("bookServiceSetter")
        public class BookService {
        
            private BookDAO bookDAO;
        
            /* BookDAO 타입의 빈 객체를 setter에 자동으로 주입해준다. */
            @Autowired
            public void setBookDAO(BookDAO bookDAO) {
                this.bookDAO = bookDAO;
            }
        }
        ```
        

#### 생성자 주입

필드를 final 로 만들고 생성자를 만들어 놓으면 클래스와 필드타입을 다 bean 으로 관리하고 있다면 알아서 주입을 해준다.

생성자가 하나뿐이라면 `@Autowired` 를 생략할 수 있다.

- 의존 객체의 내용물이 없이 생성되는 상황을 방지할 수 있다.
- final 필드를 사용하여 재할당 되는 것을 방지할 수 있다.

```java
package com.ohgiraffers.section01.autowired.constructor;

import com.ohgiraffers.section01.common.BookDAO;
import com.ohgiraffers.section01.common.BookDTO;
import org.springframework.stereotype.Service;

import java.util.List;

@Service("bookServiceConstructor")
public class BookService {

    private final BookDAO bookDAO;

		// BookDAO 를 구현한 BookDAOImpl 도 @Repository 로 bean 으로 관리 중
    // bean 을 만들기 위해 생성자를 호출할 때 알아서 주입해준다.
//    @Autowired  // 생성자 주입의 경우 생성자가 하나뿐이라면 @Autowired 를 생략해도 동작한다.
    public BookService(BookDAO bookDAO) {
        this.bookDAO = bookDAO;
    }

    public List<BookDTO> selectAllBooks() {
        return bookDAO.selectBookList();
    }

    public BookDTO searchBookBySequence(int sequence) {
        return bookDAO.selectOneBook(sequence);
    }
}
```

```java
package com.ohgiraffers.section01.autowired.constructor;

import org.springframework.context.ApplicationContext;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;

public class Application {

    public static void main(String[] args) {
        ApplicationContext context = new AnnotationConfigApplicationContext("com/ohgiraffers/section01");

        BookService bookService = context.getBean("bookServiceConstructor", BookService.class);

        /* forEach 메소드는 함수형 프로그래밍 스타일을 지원 */
        bookService.selectAllBooks().forEach(System.out::println);
        System.out.println(bookService.searchBookBySequence(1));
    }
}
```

#### 같은 타입의 구현체 구분
같은 타입 인터페이스 구현체가 여러 개 있는데 아무 처리 안하고 DI를 시키려고 하는 경우 `NoUniqueBeanDefinitionException` 오류가 발생한다.

- `@Primary` : `@Autowired` 로 동인한 타입의 여러 빈을 찾게 되는 경우 자동으로 연결 우선 시 할 타입으로 설정된다. 동일한 타입의 클래스 중 한 개만 사용 가능. 빈이 불리는 쪽에서 사용한다.
    
    ```java
    @Component
    @Primary
    /* @Autowired 로 동일한 타입의 여러 빈을 찾게 되는 경우 자동으로 연결 우선 시 할 타입으로 설정
    * 동일한 타입의 클래스 중 한 개만 @Primary 어노테이션을 사용 가능 */
    public class Charmander implements Pokemon {
    
    	@Override
    	public void attack() {
    		System.out.println("파이리 불꽃 공격");
    	}
    }
    ```
    
- `@Qualifier` : 특정 bean 객체를 이름으로 지정하는 어노테이션이다. `@Primary` 어노테이션과 함께 쓰였을 때 `@Qualifier` 가 우선 된다. 빈을 찾는 쪽에서 사용한다.
    
    ```java
    @Service("pokemonServiceQualifier")
    public class PokemonService {
        private final Pokemon pokemon;
    
    		/* @Qualifier 어노테이션은 특정 bean 객체를 이름으로 지정하는 어노테이션이다.
    		 * @Primary 어노테이션과 함께 쓰였을 때 @Qualifier 가 우선 된다. */
        @Autowired
        public PokemonService(@Qualifier("pikachu") Pokemon pokemon) {
            this.pokemon = pokemon;
        }
    
        public void pokemonAttack() {
            pokemon.attack();
        }
    }
    ```
    
- **같은 타입의 bean 을 모두 사용해야 할 경우** List 로 받으면 스프링이 알아서 **모든 같은 타입을 List 로** 전해준다.
    
    ```java
    @Service("pokemonServiceCollection")
    public class PokemonService {
        private final List<Pokemon> pokemonList;
    
        @Autowired
        public PokemonService(List<Pokemon> pokemonList) {
            this.pokemonList = pokemonList;
        }
    
        public void pokemonAttack() {
            pokemonList.forEach(Pokemon::attack);
        }
    }
    ```
