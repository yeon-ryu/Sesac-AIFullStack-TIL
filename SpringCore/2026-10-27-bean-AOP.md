# Spring Core
## Bean

**기본적으로 Spring Bean 은 싱글톤 방식**으로 관리한다. 그렇기에 ApplicationContext.getBean() 으로 같은 이름으로 가져오는 객체는 같은 객체이다.

- `@Scope("prototype")` : prototype 으로 설정된 bean 은 getBean() 으로 호출할 때마다 새로운 인스턴스를 반환한다.
    
    ```java
    @Configuration
    public class ContextConfiguration {
        @Bean
        public Product carpBread() { return new Bread("붕어빵", 1000, new Date()); }
    
        @Bean
        public Product milk() { return new Beverage("딸기우유", 1500, 500); }
    
        @Bean
        public Product water() { return new Beverage("지리산암반수", 3000, 500); }
    
        @Bean
        /* prototype 으로 설정된 bean 은 getBean() 으로 호출할 때마다 새로운 인스턴스 반환 */
        @Scope("prototype")
        public ShoppingCart cart() { return new ShoppingCart(); }
    }
    ```
    

### 라이프사이클

컨테이너 시작 → Bean 생성 → 초기화 메소드 → Bean 사용 → 컨테이너 종료(Bean 소멸 전 소멸 메소드)

외부 라이브러리를 Bean 으로 등록해야할 때 많이 활용

- 초기화 메소드 (initMethod) : Bean 생성 직후에 해당 메소드 실행
- 소멸 메소드 (destroyMethod) : 컨테이너가 종료 전 소멸 메소드로 실행
    - 필요한 경우 자원 정리에 주로 사용

```java
@Configuration
public class ContextConfiguration {
    // 초기화 메소드 (initMethod) : Bean 생성 직후에 해당 메소드 실행
    // 소멸 메소드 (destroyMethod) : 컨테이너가 종료 전 소멸 메소드로 실행
    @Bean(initMethod = "openShop", destroyMethod = "closeShop")
    public Owner owner() {
        return new Owner();
    }
}
```

```java
public class Owner {
    public void openShop() {
        System.out.println("가게 문을 열었습니다.");
    }

    public void closeShop() {
        System.out.println("가게 문을 닫았습니다.");
    }
}
```

```java
public class Application {
    public static void main(String[] args) {
        ApplicationContext context = new AnnotationConfigApplicationContext(ContextConfiguration.class);
        System.out.println("영업 중입니다.");

        // 컨테이너 종료 (컨테이너는 명시하지 않으면 그냥 종료되지 않는다.)
        // ApplicationContext 에는 close() 가 존재하지 않기에 사용하려면 AnnotationConfigApplicationContext 로 다운캐스팅 필요
        ((AnnotationConfigApplicationContext) context).close();
    }
}
```

### Properties 사용

resources 안 쪽에 자바와 스프링이 실행 중에 찾는 파일들이 들어간다. (실행 중 바뀔 가능성 있는 파일들은 외부의 properties에 넣는게 좋음 / 노출돼도 되는 정보만)

- resources 는 `classpath:` 로 경로 설정이 된다.
- `@PropertySource` : 설정 클래스에서 사용할 외부 설정 파일을 spring 환경에 등록
- `@Value` : properties 의 key 를 기준으로 문자열 값을 찾아 필드 타입에 맞게 변환하여 주입

```yaml
# resources/section03/properties/product-info.properties
bread.carpbread.name=붕어빵
bread.carpbread.price=1000
beverage.milk.name=딸기우유
beverage.milk.price=1500
beverage.milk.capacity=500
beverage.water.name=지리산암반수
beverage.water.price=3000
beverage.water.capacity=500
```

```java
@Configuration
// 설정 클래스에서 사용할 외부 설정 파일을 spring 환경에 등록
@PropertySource(value = "classpath:section03/properties/product-info.properties", encoding = "UTF-8")
public class ContextConfiguration {
    /* @Value 가 properties 의 key 를 기준으로 문자열 값을 찾아 필드 타입에 맞게 변환하여 주입 */
    @Value("${bread.carpbread.name}")
    private String carpBreadName;

    @Value("${bread.carpbread.price}")
    private int carpBreadPrice;

    @Value("${beverage.milk.name}")
    private String milkName;

    @Value("${beverage.milk.price}")
    private int milkPrice;

    @Value("${beverage.milk.capacity}")
    private int milkCapacity;
    
    @Bean
    public Product carpBread() {
        return new Bread(carpBreadName, carpBreadPrice, new Date());
    }

    @Bean
    public Product milk() {
        return new Beverage(milkName, milkPrice, milkCapacity);
    }
    
    @Bean
    public Product water(@Value("${beverage.water.name}") String waterName
            , @Value("${beverage.water.price}") int waterPrice
            , @Value("${beverage.water.capacity}") int capacity) {
        return new Beverage(waterName, waterPrice, capacity);
    }
}
```

## AOP

Aspect Oriented Programming (관점 지향 프로그래밍) : 중복되는 공통 코드를 분리하고 코드 실행 전이나 후의 시점에 해당 코드를 삽입함으로써 소스 코드의 중복을 줄이고, 필요할 때마다 가져다 쓸 수 있게 객체화하는 기술

- Aspect : 모듈화한 기본 단위
- Advice : Aspect 의 기능 자체. Logging, Security, 트랜잭션 등의 구현체
    - Before : 메소드 전 실행
    - After-returning : 메소드 정상 동작 후 실행
    - After-throwing : 예외 발생 후 실행
    - After : 메소드 후 실행
    - Around : 메소드 전후 실행
- Join point : Advice 가 적용될 수 있는 위치 (Advice 가 적용될 메소드)
- Pointcut : Join point 중에서 Advice 가 적용될 가능성이 있는 부분을 선별한 것 (Advice 적용 조건)
- Weaving : Adivce 를 핵심 비지니스 로직에 적용한 것

proxy 가 요청을 가로채서 실행되도록 한다.

### AOP어노테이션

- `@Aspect` : 이 클래스가 AOP 의 적용 위치와 실행할 동작을 정의한다는 뜻
- `@Pointcut` : 공통 기능을 적용할 메소드의 조건을 이름(디폴트는 메소드 이름 ex.serviceMethods)을 붙여서 보관
- `JoinPoint` : 실행될 메소드의 정보

- `@Before` : 해당 포인트 컷 조건식에 맞는 모든 메소드 실행 전 수행
- `@After` : `@AfterReturning` , `@AfterThrowing` 이후에 실행된다.
- `@AfterReturning` : returning 속성 존재. 해당 속성으로 결과 값을 매개변수로 받아 사용 가능
- `@AfterThrowing` : throwing 속성 존재. 해당 속성으로 throw 된 값을 매개변수로 받아 사용 가능

- `@Around` : 대상 메소드 실행 전/후에 사용되는 어드바이스로, 조인포인트를 완전히 장악하기에 원본 메소드 호출까지 제어한다. 그렇기에 호출하는 코드를 안 적으면 원본 메소드가 실행되지 않을 수도 있다. (proceed() 를 호출해야 원래 메소드가 실제로 실행됨)

```java
package com.ohgiraffers.section01.aop;

import org.aspectj.lang.JoinPoint;
import org.aspectj.lang.ProceedingJoinPoint;
import org.aspectj.lang.annotation.*;
import org.springframework.stereotype.Component;

import java.util.Arrays;

/* @Aspect : 이 클래스가 AOP 의 적용 위치와 실행할 동작을 정의한다는 뜻 */
@Aspect
@Component
public class LoggingAspect {

    /* @Pointcut : 공통 기능을 적용할 메소드의 조건을 이름(디폴트는 메소드 이름 ex.serviceMethods)을 붙여서 보관 */
    // 제일 앞 * : 반환 타입과 관계없이
    // .*Service : 이름이 Service 로 끝나는 모든 클래스
    // .*(..) : 모든 메소드, 모든 매개변수
    @Pointcut("execution(* com.ohgiraffers.section01.aop.*Service.*(..))")
    public void serviceMethods() {
    }

    /* @Before : 해당 포인트컷 조건식에 맞는 모든 메서드 실행 전 수행 */
    @Before("serviceMethods()")
    // Advice : 실행할 공통 기능
    public void logBefore(JoinPoint joinPoint) { /* JoinPoint : 실행될 메소드의 정보 */
        System.out.println("[Before]" + joinPoint.getSignature().getName()
            + " args=" + Arrays.toString(joinPoint.getArgs()));
    }

    // returning="result" : 대상 메소드가 반환한 값을 Advice 의 result 매개변수로 받겠다는 뜻
    // 속성에 적은 이름과 매개변수 이름이 같아야 한다.
    @AfterReturning(pointcut = "serviceMethods()", returning = "result")
    public void logAfterReturning(JoinPoint joinPoint, Object result) {
        System.out.println("[AfterReturning]" + joinPoint.getSignature().getName()
            + " result=" + result);
    }

    // throwing="exception" : 대상 메소드가 밖으로 던진 예외를 Advice 의 exception 매개변수로 받겠다는 뜻
    @AfterThrowing(pointcut = "serviceMethods()", throwing = "exception")
    public void logAfterThrowing(JoinPoint joinPoint, Throwable exception) {
        System.out.println("[AfterThrowing]" + joinPoint.getSignature().getName()
                + " message=" + exception.getMessage());
    }

    @After("serviceMethods()")
    public void logAfter(JoinPoint joinPoint) {
        System.out.println("[After]" + joinPoint.getSignature().getName());
    }

    // 메소드 실행 전후에 수행되고 메소드 실행 시점까지 제어 가능 (대상 메소드 실행을 작성하지 않으면 실행되지 않을 수도 있다)
    @Around("serviceMethods()")
    public Object logExecutionTime(ProceedingJoinPoint joinPoint) throws Throwable {
        long startTime = System.nanoTime();

        try {
            // 대상 메소드 호출
            // Before ~ After 까지 대상 메소드 포함 전부 실행됨
            return joinPoint.proceed();
        } finally {
            long elapsedTime = System.nanoTime() - startTime;
            System.out.println("[Around] elapsed=" + elapsedTime);
        }

    }
}
```

#### Proxy

Proxy : 대리 객체

- `@EnableAspectJAutoProxy` : AOP 동작을 할 수 있는 proxy 로 Bean 을 감싼다. 호출하면 proxy 가 먼저 받아서 AOP 적용하고 서비스로 넘겨준다.

```java
package com.ohgiraffers.section01.aop;

import org.springframework.context.annotation.ComponentScan;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.EnableAspectJAutoProxy;

@Configuration
@ComponentScan("com.ohgiraffers.section01.aop")
@EnableAspectJAutoProxy
public class ContextConfiguration {
}
```
