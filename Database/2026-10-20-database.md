# Database

## 기본 개념

- Data : 관찰의 결과로 나타난 **정량적 혹은 정석적인 실제 값**
- Information : 데이터를 기반으로 하여 **의미를 부여한 것**

- Database : 필요한 정보를 여러 응용 시스템에서 공유할 수 있도록 논리적으로 연관된 데이터를 모으고, **중복되는 데이터를 최소화**하여 **구조적으로 통합/저장**해 놓은 것

### Database 의 특징

- 실시간 접근성
- 계속적인 변화
- 동시 공유
- 내용에 따른 참조

## DBMS (Database Management System)

데이터베이스 전용 관리 프로그램

DBMS 의 기능

- 데이터 추출
- 데이터 조작
- 데이터 정의
- 데이터 제어

DBMS 사용 이점

- 데이터 중복 최소화
- 쿼리 언어 : SQL 과 같은 쿼리 언어 제공
- 데이터 무결성 : 다양한 제약 조건과 규칙을 설정 가능
- 데이터 백업 및 복구 : 데이터의 백업과 복구를 지원
- 표준화 : 표준화된 방법으로 데이터를 관리하여 개발 유지보수가 용이해짐

## MySQL

관계형 데이터베이스 관리 시스템(RDBMS)

- 무료 오픈소스

### 쿼리 실행 과정

클라이언트/서버 통신 → 쿼리 파싱 → 최적화 및 실행 계획 생성 → 쿼리 실행 → 결과 반환

1. 클라이언트/서버 통신 : 클라이언트(워크벤치, 프로그래밍 언어 API 등)에서 SQL 쿼리를 MySQL 서버로 전송
2. 쿼리 파싱 : SQL 문장을 이해할 수 있는 단위로 나누고 문법이 유효한지, 키워드가 올바른지, 컬럼과 테이블이 실제로 존재하는지, 문법에 오류가 없는지를 확인. 오류가 있을 경우 오류 메세지를 반환하고 프로세스를 중단한다.
    1. 렉시컬 분석
    2. 구문 분석
    3. 의미 분석
3. 최적화 및 실행 계획 생성 : 파싱이 성공하면, 효율적으로 실행할 수 있는 방버 결정
4. 쿼리 실행 : 실행 계획에 따라 실제 데이터베이스 파일 또는 인덱스에 접근
5. 결과 반환 : MySQL 서버가 결과 세트를 클라이언트에게 반환

### ORDER BY

- FIELD(컬럼, 첫번째, 두번째, ...) : 컬럼 값이 목록의 몇 번째에 있는지 숫자로 알려준다.
    - ORDER BY FIELD(orderable_status, 'N', 'Y'); -- orderable_status 의 값이 ‘N’ 일 경우 1, 값이 ‘Y’ 일 경우 2 가 된다

```sql
# ORDER BY 기준컬럼
-- SELECT 문의 가장 마지막에 위치하며, 결과 집합을 하나의 열로 정렬

-- 오름차순 (ASC) (생략 가능)
SELECT * FROM tbl_menu ORDER BY menu_price;

-- 내림차순 정렬 (DESC) (생략 불가능)
-- 2차 기준 ',' 로 추가 (1차 기준이 같을 경우 적용)
SELECT * FROM tbl_menu ORDER BY menu_price DESC, menu_name ASC;

-- 연산 결과로 정렬
SELECT menu_code, menu_price, menu_code * menu_price as calculated_value FROM tbl_menu order by calculated_value DESC;

-- FIELD(컬럼, 첫번째, 두번째, ...) : 컬럼 값이 목록의 몇 번째에 있는지 숫자로 알려준다.
SELECT FIELD('B', 'A', 'B', 'C'); -- B 는 뒤의 목록 중 2번째에 있기에 2 가 반환됨

-- 'N' 을 1순위, 'Y' 를 2순위로 정렬
SELECT menu_name, orderable_status FROM tbl_menu
ORDER BY FIELD(orderable_status, 'N', 'Y'); -- 값이 N 일 경우 1, 값이 Y 일 경우 2 가 된다

-- null 값이 있는 컬럼은 오름차순 시 가장 앞 쪽에 놓인다.
select * from tbl_category order by ref_category_code;

-- IS NULL : null 이면 true(1), 아니면 false(0) 를 반환
-- 먼저 null 이 아니면 0 이고 null 이면 1 인걸로 오름차순하고 그 뒤 null 이 아닌 값들 정렬
-- null 값이 가장 뒤로 이동한다.
select * from tbl_category order by ref_category_code is null, ref_category_code;

-- 내림차순 시 null 을 처음으로 (IS NULL DESC)
select * from tbl_category order by ref_category_code is null DESC, ref_category_code DESC;
```

### WHERE

비교 연산자

- `<>` : 같지 않다.
- `=`
- `<`
- `<=`

논리 연산자

- AND (우선순위가 OR보다 높다)
- OR

아래 연산자들 부정을 하려면 앞에 NOT 을 붙인다.

- BETWEEN 값1 AND 값2 : 값1 이상 값2 이하 (**시작과 끝을 포함**)
- LIKE ‘%값%’ : 값이 포함된 결과값 반환. % 는 문자가 없거나 여러 개 있어도 된다는 와일드 카드이다.
- IN (A, B, C) 연산자 : 값이 A거나, B거나, C인 데이터
- IS NULL : null 값을 찾는다.
- IFNULL(컬럼명, 표시할 값)

```sql
# WHERE 조건
-- '조건 필터링'의 역할, 특정 조건에 맞는 행만 선택하는데 사용된다.
-- (1) 비교 연산자 활용 (=, <>, >, <=)

-- <> : 같지 않다
SELECT * FROM tbl_menu
WHERE orderable_status <> 'Y'; -- 이 조건이 true 가 되는 행들만 결과에 포함

-- (2) 논리 연산자 (AND, OR)를 활용하여 조건 조합
-- AND (두 조건이 모두 참이어야 함), OR (둘 중 하나라도 참이면 참)
-- 주문 가능하면서(Y), 카테고리가 10번인 메뉴 찾기
SELECT * FROM tbl_menu
WHERE orderable_status = 'Y' AND category_code = 10;

-- 우선순위 (AND > OR) -> 순서를 명확하게 하고 싶으면 소괄호 사용
SELECT 1 OR 0 AND 0; -- 결과 : 1, 1 OR 0 이 된다
SELECT (1 OR 0) AND 0; -- 결과 : 0

-- 가격이 만원 이상이고, 2만 5천원 이하인 메뉴 찾기
SELECT * FROM tbl_menu WHERE menu_price BETWEEN 10000 AND 25000;
SELECT * FROM tbl_menu WHERE menu_price NOT BETWEEN 10000 AND 25000;

-- LIKE
-- 메뉴 이름에 '마늘' 이 포함된 메뉴를 찾고 싶을 때
-- % 는 문자가 없거나 여러 개 있어도 된다는 와일드 카드이다.
SELECT * FROM tbl_menu WHERE menu_name LIKE '%마늘%'; -- 이름 어느 위치에든 마늘이 포함된 메뉴를 찾는다.
-- LIKE '%마늘' : 마늘로 끝남
-- LIKE '마늘%' : 마늘로 시작함

-- IN 연산자
-- 카테고리 코드가 4번이거나, 5번이거나, 6번인 메뉴 찾기
SELECT * FROM tbl_menu WHERE category_code IN (4, 5, 6); -- 부정은 NOT IN

SELECT category_code, category_name, IFNULL(ref_category_code, -1) FROM tbl_category;

-- IS NULL
SELECT category_code, category_name, ref_category_code FROM tbl_category WHERE ref_category_code IS NULL; -- 부정은 IS NOT NULL
```

### DISTINCT

`DISTINCT 칼럼명`

열이 여러 개 일 경우, 지정된 모든 열의 조합이 같을 때만 중복으로 간주하여 제거

```sql
# DISTINCT (중복 제거)
-- 중복된 값을 제거하고 고유한 값들의 목록만 보고 싶을 때 사용

SELECT DISTINCT category_code FROM tbl_menu ORDER BY category_code;

-- 열이 여러 개인 DISTINCT
-- 지정된 모든 열의 조합이 똑같을 때만 중복으로 간주하여 제거

SELECT DISTINCT category_code, orderable_status FROM tbl_menu;
```

### LIMIT

`LIMIT 갯수`

LIMIT 시작 인덱스(0부터 시작), 갯수

```sql
# LIMIT 개수
-- 결과 중에 딱 내가 원하는 만큼만 잘라서 달라고 요청하는 키워드

SELECT * FROM tbl_menu ORDER BY menu_price DESC LIMIT 5;

-- LIMIT [시작 위치(실질 건너뛸 갯수)], [가져올 행 갯수]

```

### JOIN

`FROM 테이블A JOIN 테이블B ON 연결조건`

INNER JOIN : 교집합

- JOIN : INNER JOIN 해도 똑같은 결과가 나온다.

OUTER JOIN : 합집합

- LEFT JOIN : JOIN 구문을 기준으로 왼쪽 테이블의 데이터는 모두 보여주고, 오른쪽 테이블에서 짝이 맞는 데이터가 없으면 'NULL' 로 채워서 보여준다.
    - SELF JOIN : 같은 테이블 안에서 행과 행의 관계가 있는 경우, 그걸 연결해서 보고 싶을 때 자기 자신과 셀프 조인 한다.
- RIGHT JOIN
    - FULL OUTER JOIN : LEFT JOIN 과 RIGHT JOIN 을 해서 UNION 시켜야 함

```sql
# JOIN

select * from tbl_menu;
select * from tbl_category;

-- 테이블 별칭은 JOIN 에서 필수
-- 띄어쓰기가 있을 경우 따옴표 사용, 간단할 경우 as 나 따옴표 생략 가능
SELECT a.menu_name as '메뉴 이름', a.menu_price as price, b.category_name as 카테고리
FROM tbl_menu a
LEFT JOIN tbl_category b ON a.category_code = b.category_code
ORDER BY price desc;

-- INNER JOIN : 교집합 (가장 기본적인 조인)
SELECT a.menu_name, b.category_name
FROM tbl_menu a
JOIN tbl_category b ON a.category_code = b.category_code; -- ON : 같은 행을 찾을 연결 조건

-- OUTER JOIN (LEFT / RIGHT)
-- LEFT JOIN : JOIN 구문을 기준으로 왼쪽 테이블의 데이터는 모두 보여주고, 오른쪽 테이블에서 짝이 맞는 데이터가 없으면 'NULL' 로 채워서 보여준다.
-- INNER JOIN 이 포함되어 있으니까 짝이 있으면 전부 출력됨
SELECT a.category_name, b.menu_name
FROM tbl_category a -- 왼쪽 테이블
LEFT JOIN tbl_menu b ON a.category_code = b.category_code
ORDER BY a.category_code;

-- SELF JOIN (같은 테이블 안에서 행과 행의 관계가 있는 경우, 그걸 연결해서 보고 싶을 때 셀프 조인을 할 수 있다.)
select a.category_code, a.category_name '하위 카테고리', b.category_name '상위 카테고리'
FROM tbl_category a -- '하위' 역할을 할 a 테이블
LEFT JOIN tbl_category b ON a.ref_category_code = b.category_code -- '상위' 역할을 할 b 테이블
order by a.category_code;
```

### GROUP BY

여러 컬럼을 group by 에 걸어주면 해당 컬럼들의 조합을 기준으로 묶어준다.

GROUP BY 를 사용하면 GROUP BY 에 사용된 컬럼과 집계 함수만 올 수 있다.

- COUNT() : 각 그룹에 속한 행의 개수를 센다
- SUM() : 합계
- AVG() : 평균

- ROLLUP : 그룹별 집계 결과와 함께 그 그룹들의 소계와 총계를 보여줌 `with rollup` 으로 사용
    - category_code 가 null 이고 '가격 총합' 항목에 sum 들의 합계가 나타난 행이 추가됨
- HAVING : 그룹화된 데이터를 조건 필터링 (WHERE 은 그룹화 전 조건 필터링이다)

```sql
# GROUP BY
-- 지정된 칼럼의 값이 같은 데이터들을 하나의 그룹으로 묶는다.

-- COUNT() : 각 그룹에 속한 행의 개수를 센다
-- SUM(), AVG()
SELECT category_code, count(menu_code) '메뉴 개수', sum(menu_price) '가격 총합', avg(menu_price) '가격 평균'
FROM tbl_menu
GROUP BY category_code
ORDER BY avg(menu_price) DESC;

-- GROUP BY 를 사용하면 GROUP BY 에 사용된 컬럼과 집계 함수만 올 수 있다.

-- HAVING : 그룹화된 데이터를 조건 필터링 (WHERE 은 그룹화 전 조건 필터링이다)
SELECT category_code, count(menu_code) '메뉴 개수', sum(menu_price) '가격 총합', avg(menu_price) '가격 평균'
FROM tbl_menu
GROUP BY category_code
HAVING count(*) >= 3;

-- ROLLUP : 그룹별 집계 결과와 함께 그 그룹들의 소계와 총계를 보여줌
SELECT category_code, sum(menu_price) '가격 총합'
FROM tbl_menu
GROUP BY category_code
WITH ROLLUP; -- category_code 가 null 이고 '가격 총합' 항목에 sum 들의 합계가 나타난 행이 추가됨

-- 가격대별, 그 안에서 카테고리별로 그룹화 하고 ROLLUP 적용
SELECT menu_price, category_code, SUM(menu_price)
FROM tbl_menu
GROUP BY menu_price, category_code
WITH rollup;
```

### 서브 쿼리

- 파생 테이블 : 서브 쿼리를 FROM 절 에 사용할 경우 나온 값을 파생 테이블이라 칭하고, 파생 테이블은 반드시 별칭이 있어야 한다.
- 상관 서브 쿼리 :  바깥쪽 별칭을 사용하여 바깥의 값 사용

```sql
# SUBQUERIES (서브쿼리)

-- 1단계 서브쿼리
SELECT category_code FROM tbl_menu
WHERE menu_name = '민트미역국';

-- 2단계 메인쿼리
-- 민트미역국과 같은 카테고리 메뉴 조회
SELECT menu_name, category_code FROM tbl_menu
WHERE category_code = (
	SELECT category_code FROM tbl_menu
	WHERE menu_name = '민트미역국'
);

-- FROM 절에서 서브쿼리 사용
-- 즉석에서 만들어 쓰는 임시 테이블처럼 동작 -> 파생 테이블이라고도 한다.

-- 가장 많은 메뉴가 포함된 카테고리는 메뉴를 총 몇 개 가지고 있나요?

-- 1단계 서브쿼리 : 카테고리별로 메뉴가 몇 개씩 있는지?
SELECT COUNT(*) AS 'count' FROM tbl_menu
GROUP BY category_code;

-- 2단계 : 가장 많은 메뉴가 포함된 카테고리의 메뉴 수
SELECT MAX(count) AS '최대 메뉴 수' FROM (
	SELECT COUNT(*) AS 'count' FROM tbl_menu
	GROUP BY category_code
) AS count_table; -- 파생 테이블은 반드시 별칭이 있어야 한다.

-- 상관 서브쿼리
-- 카테고리별 평균 가격보다 높은 가격의 메뉴 조회
SELECT avg(menu_price) FROM tbl_menu
WHERE category_code = 4;

SELECT menu_code, menu_name, menu_price FROM tbl_menu a
WHERE menu_price > (
	SELECT avg(menu_price) FROM tbl_menu
	WHERE category_code = a.category_code
);

SELECT menu_code, menu_name, menu_price FROM tbl_menu a
WHERE menu_price > (
	SELECT avg(menu_price) FROM tbl_menu
	WHERE category_code = a.category_code
)
```

### UNION

집합 연산자

**UNION** : 두 결과를 위아래로 합치고 자동으로 **중복은 제거**

- 조회하는 컬럼이 같아야 한다

UNION ALL : 두 결과를 합치기 (중복 포함)

MySQL 은 교집합, 차집합 집합 연산자를 제공해주지 않기 때문에 JOIN 을 활용해야 한다.

```sql
# SET OPERATORS (집합 연산자)

-- 카테고리 코드가 10번인 메뉴들과 가격이 9,000원 미만인 메뉴들

-- UNION : 두 결과를 합치기(자동으로 중복은 제거)
SELECT menu_name, menu_price, category_code FROM tbl_menu
WHERE category_code = 10
UNION
SELECT menu_name, menu_price, category_code FROM tbl_menu
WHERE menu_price < 9000;

-- UNION ALL : 두 결과를 합치기(중복 포함)
SELECT menu_name, menu_price, category_code FROM tbl_menu
WHERE category_code = 10
UNION ALL
SELECT menu_name, menu_price, category_code FROM tbl_menu
WHERE menu_price < 9000;

-- 교집합
-- INNER JOIN 활용
-- 9천원 미만인 메뉴만 출력
SELECT a.menu_code, a.menu_price, a.category_code FROM tbl_menu a
JOIN (SELECT menu_code, menu_price FROM tbl_menu
	WHERE menu_price < 9000
) b ON a.menu_code = b.menu_code;

-- 카테고리가 10번이면서 9천원 미만인 메뉴만 출력
SELECT menu_code, menu_price, category_code FROM tbl_menu
WHERE category_code = 10
AND menu_code IN (SELECT menu_code FROM tbl_menu
	WHERE menu_price < 9000
);

-- 차집합
-- 10번 카테고리 메뉴 중에서 가격이 9천원 미만인 메뉴를 제외하는 차집합 조회
SELECT a.menu_code, a.menu_price, a.category_code FROM tbl_menu a
LEFT JOIN (SELECT menu_code FROM tbl_menu
	WHERE menu_price < 9000
) b ON a.menu_code = b.menu_code
WHERE a.category_code = 10 AND b.menu_code IS NULL;
```

## DML

DML(Data Manipulation Language, 데이터 조작어) : 데이터베이스에 저장된 데이터를 조회, 삽입, 수정, 삭제하는 데 사용되는 SQL 명령어

행을 추가/수정/삭제 할 경우 변경된 행의 개수를 반환한다.

### INSERT

새로운 행을 추가하는 구문

`INSERT INTO 테이블명 VALUES(값을 전부 순서대로);`

`INSERT INTO 테이블명(추가할 칼럼명) VALUES(칼럼에 들어갈 데이터);`

```sql
# INSERT
-- 새로운 행을 추가하는 구문
INSERT INTO tbl_menu VALUES(null, '순대국밥', 9000, 4, 'Y'); -- menu-code 는 AI PK 값이어서 자동으로 늘어난다.

-- INSERT 하고 싶은 데이터 컬럼을 지정
INSERT INTO tbl_menu(menu_name, menu_price, orderable_status, category_code)
VALUES('초콜릿', 5000, 'Y', 7);

-- 한번에 여러 행 추가
INSERT INTO tbl_menu
VALUES(null, '바닐라아이스크림', 2000, 12, 'Y'),
	(null, '딸기아이스크림', 1000, 12, 'Y'),
	(null, '녹차아이스크림', 1700, 12, 'Y');
```

### UPDATE

테이블에 이미 존재하는 행의 컬럼 값을 수정

`UPDATE 테이블명 SET 컬럼명=바꿀데이터 WHERE 바꿀대상;`

WHERE 절이 빠질 경우 테이블 내 모든 데이터가 바뀐다.

```sql
# UPDATE
-- 테이블에 이미 존재하는 행의 컬럼 값을 수정
UPDATE tbl_menu
SET category_code = 7 -- 바꿀 내용
WHERE menu_code = 22; -- 바꿀 대상
```

#### UPSERT

존재하면 UPDATE, 존재하지 않으면 INSERT 작업

```sql
INSERT INTO 테이블명 (컬럼1, 컬럼2, 컬럼3)
VALUES (값1, 값2, 값3)
ON DUPLICATE KEY UPDATE 
    컬럼2 = 값2,
    컬럼3 = 값3;
```

### DELETE

테이블에서 특정 행을 삭제하는 구문

`DELETE FROM 테이블명 WHERE 바꿀대상;`

UPDATE 와 마찬가지로 WHERE 절이 빠질 경우 테이블 내 모든 데이터가 삭제될 수 있다.

```sql
# DELETE
-- 테이블에서 특정 행을 삭제하는 구문
DELETE FROM tbl_menu
WHERE menu_code = 22;
```

### REPLACE

INSERT시 PRIMARY KEY 또는 UNIQUE KEY 가 충돌이 발생할 수 있다면, REPLACE 를 통해 중복된 데이터를 덮어 쓸 수 있다.

기존 행을 DELETE하고 새 행을 INSERT 하는 형태로 동작한다.

```sql
# REPLACE
-- INSERT시 PRIMARY KEY 또는 UNIQUE KEY 가 충돌이 발생할 수 있다면
-- REPLACE 를 통해 중복된 데이터를 덮어 쓸 수 있다.
-- INSERT INTO tbl_menu VALUES(25, '참기름', 5000, 10, 'Y'); -- 이미 존재하는 PK 값

-- 해당 키에 데이터가 있으면 기존 행을 DELETE하고 새 행을 INSERT 하는 형태로 동작하기에 2행(삭제, 추가)을 변경했다고 나온다.
REPLACE INTO tbl_menu VALUES(25, '참기름', 5000, 10, 'Y');
```

## Transaction

모두 성공하거나, 모두 실패해야하는 하나의 작업 단위

MySQL 은 기본적으로 autocommit 모드가 켜져있다. 조절하려면 설정을 바꿔줘야한다. `SET autocommit = OFF;`

- 트랜잭션 시작 : `START TRANSACTION;`
- ROLLBACK : START TRANSACTION 시점 이후에 수행했던 모든 작업을 '전부 취소'하고 트랜잭션 시작 전의 상태로 되돌린다. `ROLLBACK;`
- COMMIT : 작업이 올바르다고 판단됐을 시 최종 저장 `COMMIT;`

```sql
# Transaction (트랜잭션)
-- All or Nothing 모두 성공하거나, 모두 실패해야하는 하나의 작업 단위

-- MySQL 은 기본적으로 autocommit 모드가 켜져있다. 조절하려면 설정을 바꿔줘야한다.
SET autocommit = OFF;

-- 트랜잭션 시작
START TRANSACTION;

SELECT * FROM tbl_menu;

INSERT INTO tbl_menu VALUES(null, '순대국밥', 10000, 4, 'Y');
UPDATE tbl_menu SET menu_name = '수정한 메뉴' WHERE menu_code = 5;
DELETE FROM tbl_menu WHERE menu_code = 5;


-- ROLLBACK : START TRANSACTION 시점 이후에 수행했던 모든 작업을 '전부 취소'하고 트랜잭션 시작 전의 상태로 되돌린다.
ROLLBACK; -- COMMIT 이후에는 소용이 없다.


-- COMMIT : 작업이 올바르다고 판단됐을 시 최종 저장
COMMIT;


SET autocommit = ON;
```
