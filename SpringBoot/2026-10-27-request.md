# Spring Boot
## 개요

스프링 프레임워크에 기본 설정이나 실행을 쉽게 할 수 있게 해놓은 도구.

Spring Framework : Bean, DI, Component Scan 등을 제공  
**Spring Boot : Spring Framework + Starter 의존성 + 자동 설정 + 내장 웹 서버 + 실행 가능한 애플리케이션 구성**

HTTP 요청 = 요청 방식(HTTP 메소드) + 경로 + Header + Body  
HTTP 응답 = 상태 코드 + Header + Body

## 개발 환경

IntelliJ 에서 프로젝트 생성 시 Spring Boot 선택 (JDK21, Java21)

종속성 추가  
- Spring Web : 스프링 부트에서 web 을 하려면 거의 필수적인 의존성
  - spring-boot-starter-webmvc → tomcat, spring aop, spring core 등이 다 포함되어 있다.
- DevTools : 중간 중간 서버가 다시 시작하기에 개발할 때 변경사항 적용을 위해 개발자가 직접 서버 재시작 해야할 빈도가 줄어듬

Web Server 와 스프링 컨테이너는 다르다. 스프링 부트가 웹 서버를 켜고 스프링 컨테이너도 시작해 놓는다.

- `@SpringBootApplication` : 어플리케이션 시작점 표시 및 자동 설정, Component Scan 실시
- `@RestController` : 이 클래스가 웹 요청을 받는 Controller 이며, 메소드의 **반환 값을 HTTP 응답 본문으로 전달**한다는 표시이다. `@Controller` 와 `@ResponseBody` 의 기능을 합친 어노테이션이다.
    - `@Controller` 은 화면을 렌더링하여 반환할 때

## Request Mapping

1. HTTP Request : 클라이언트의 Request 가 DispatcherServlet 에 도착
2. Handler 조회 : HandlerMapping 을 통해 클라인언트의 요청을 매핑할 적절한 Controller 를 찾는다.
3. handle(Handler) : DispatcherServlet 이 Handler Adapter 를 실행하고 Handler Adapter 이 Handler(Controller)를 호출한다.
4. handler 호출 : Controller 의 handler method 를 호출한다. Controller 은 비지니스 로직을 거쳐 반환한다.

- 핸들러 메소드 : HTTP 요청과 연결되어 실제로 실행되는 Controller 메소드

- `.http` 파일 : 테스트할 요청을 텍스트로 작성하여 보관 → 요청 실행 가능 (결과 로그 .idea/httpRequests 에 저장됨)
    
    ```java
    // api-test.http
    ### 1. 메뉴 목록 조회
    GET http://localhost:8080/api/v1/menus
    
    ### 2. 메뉴 단건 조회
    GET http://localhost:8080/api/v1/menus/3
    
    ### 3. 메뉴 등록
    POST http://localhost:8080/api/v1/menus
    
    ### 4. 메뉴 수정
    PUT http://localhost:8080/api/v1/menus/1
    
    ### 5. 메뉴 삭제
    DELETE http://localhost:8080/api/v1/menus/1
    
    ### 6. 주문 목록 조회
    GET http://localhost:8080/api/v1/orders
    
    ### 7. 주문 상세 조회
    GET http://localhost:8080/api/v1/orders/3
    ```

```java
package com.ohgiraffers.requestmapping;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

import java.util.Map;

/*
* @RestController : @Controller 와 @ResponseBody의 기능을 합친 것이다.
* 이 컨트롤러의 모든 핸들러 메소드는 화면(View)를 반환하는 대신,
* 반환 값을 직접 HTTP 응답 몬문(JSON 형식)으로 만들어 클라이언트에게 전달한다.
* */
@RestController
@RequestMapping("/api/v1/menus") // Controller 클래스의 공통 주소 지정
public class MethodMappingTestController {

    // 핸들러 메소드 : HTTP 요청과 연결되어 실제로 실행되는 Controller 메소드
    @GetMapping()
    public ResponseEntity<Map<String, String>> findMenus() {
        // Map.of : 쉽게 Map 을 생성할 수 있다.
        Map<String, String> response = Map.of("message", "메뉴 목록 조회용 핸들러 메소드 호출");

        // 상태코드와 본문을 쉽게 표현할 수 있게 해주는 객체
        return ResponseEntity.ok(response);
    }

    @GetMapping("/{menuCode}")
    public ResponseEntity<Map<String, Object>> findMenu(
            @PathVariable("menuCode") int menuCode) {

        Map<String, Object> response = Map.of("message", menuCode + "번 메뉴 조회용 핸들러 메소드 편집");

        // 조회 성공시 보통 200 상태코드
        return ResponseEntity.ok(response);
    }

    @PostMapping
    public ResponseEntity<Map<String, String>> registMenu() {
        Map<String, String> response = Map.of("message", "신규 메뉴 등록용 핸들러 메소드 호출");

        // 등록을 성공했을 때는 보통 201 상태코드를 반환한다.
        return ResponseEntity.status(HttpStatus.CREATED).body(response);
    }

    @PutMapping("/{menuCode}")
    public ResponseEntity<Map<String, String>> modifyMenu(@PathVariable int menuCode) {
        Map<String, String> response = Map.of("message", menuCode + "번 메뉴 수정용 핸들러 메소드 호출");

        return ResponseEntity.ok(response);
    }

    @DeleteMapping("/{menuCode}")
    public ResponseEntity<Map<String, String>> deleteMenu(@PathVariable("menuCode") int menuCode) {
        Map<String, String> response = Map.of("message", menuCode + "번 메뉴 삭제용 핸들러 메소드 호출");

        return ResponseEntity.ok(response);
    }
}
```
