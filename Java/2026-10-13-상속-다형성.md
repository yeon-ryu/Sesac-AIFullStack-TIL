# 상속
공통 상태와 기능을 부모 클래스에 정의하고, 자식 클래스가 그것을 이어받아 사용하거나 자신의 목적어 맞게 확장하는 방법

- IS-A 관계 : 부모 자식 관계 `public class 클래스명 extends 부모클래스 { }`
- protected : 같은 패키지나 상속받은 자식 클래스에서 접근 가능
- super() : 부모 클래스의 생성자를 호출 (안 적더라도 컴파일러가 알아서 추가해준다.)

## 초기화

```java
public class Computer extends Product {

    private String cpu;
    private int ram;

    public Computer() {
        super();

        System.out.println("Computer 기본 생성자 호출");
    }

    // 부모와 자식 필드를 모두 초기화하는 생성자
    public Computer(String code, String name, int price, String cpu, int ram) {
        super(code, name, price);
        this.cpu = cpu;
        this.ram = ram;

        System.out.println("Computer 클래스의 부모 필드도 초기화하는 생성자 호출");
    }
}
```

## 오버라이딩

부모에게 물려받은 메소드를 자식의 목적에 맞게 같은 형태로 다시 재정의하는 것

`@Override` : 컴파일러가 부모의 메소드를 올바르게 재정의했는지 검사 (어노테이션 존재여부는 오버라이딩에 영향을 끼치지 않는다.)

```java
public class FireCar extends Car {
    public FireCar() {
        super(); // 부모 클래스의 기본 생성자를 호출
        System.out.println("FireCar 기본 생성자 호출...");
    }

    /* 오버라이딩
    * 부모에게 물려받은 메소드를 자식의 목적에 맞게 같은 형태로 다시 재정의하는 것 */
    @Override // 컴파일러가 부모 메소드를 올바르게 재정의했는지 검사
    public void soundHorn() {
        if(isRunning()) {
            System.out.println("빠아아앙!!!!");
        } else {
            System.out.println("소방차가 주행 중이 아닙니다.");
        }
    }

    public void sprayWater() {
        System.out.println("불난 곳을 발견했습니다. 물을 뿌립니다!!🚿🚿");
    }
}
```

부모에게 과하게 의지하면 부모가 바꼈을 때 영향이 크기 때문에 필요한 것만 오버라이딩

### 오버라이딩 규칙

```
오버라이딩 성공 조건
- 메소드 이름과 매개변수 목록이 부모와 동일해야 한다.
- 반환 타입도 부모와 동일하게 작성하는 것이 기본이다. (부모 반환 타입의 자식 타입이라면 가능)
- 접근 제한자는 부모와 같거나 더 넓어야 한다. (private < default < protected < public)

오버라이딩 불가 대상
- private 메소드 (자식에게 보이지 않음)
- final 메소드 (변경이 금지됨)
- 생성자 (상속되지 않음)
```

- 메소드 이름, 반환 타입, 매개변수 시그니처가 일치해야 한다.
- private 메소드 : 클래스 내부에서만 보이기에 오버라이딩 불가 (그냥 별개의 메소드)
- **final** : 호출은 가능, **재정의(오버라이딩) 금지** → 모든 자식이 같은 규칙을 사용하게 하기 위해 사용된다.
- 오버라이딩 할 때, protected → public 처럼 **부모보다 더 넓은 접근 제한자로 바꿀 수 있다**.

오버라이딩 불성립

- 이름이 일치하지 않을 경우
- 반환형이 다른 경우
- 매개변수가 다를 경우
- private, final 메소드
- 접근 범위 축소 (접근 제한자)
- 생성자 오버라이딩 불가


# 다형성
부모 타입 하나로 여러 자식 객체를 다룰 수 있다.

같은 메소드를 호출해도 실제 객체에 따라 다른 동작이 실행되는 성질이다.

**동적 바인딩** : 컴파일 시점에는 부모의 메소드를 가리키고 있다가 **실행 시점(런타임) 때 참조 변수가 실제로 가리키는 객체로 연결**됨 → 오버라이딩 된 메소드가 실행되는 원리

- 업 캐스팅 : 자식 객체의 참조값을 부모 타입 변수에 저장 (실제 객체는 자식 객체 그대로 이지만, 바라보는 시선만 부모 타입으로 변한 것)
- 다운 캐스팅 : 자식 타입으로 명시적 형변환

```java
package com.ohgiraffers.section01.polymorphism;

public class Zookeeper {
    // 매개변수에 다형성 적용
    public void feed(Animal animal) {
        animal.eat();
    }

    /* 다형성 적용 안할 경우
    public void feed(Rabbit rabbit) {
        rabbit.eat();
    }

    public void feed(Tiger tiger) {
        tiger.eat();
    }
    */
}
```

```java
package com.ohgiraffers.section01.polymorphism;

public class Application {
    public static void main(String[] args) {
        /*
        * [다형성]
        * 하나의 부모 타입으로 여러 자식 객체를 다룰 수 있다.
        * 같은 메소드를 호출해도 실제 객체에 따라 다른 동작이 실행되는 성질이다.
        *
        * 부모 타입 찹조변수로 자식 객체를 찹조할 수 있다.
        * 부모타입 변수 = new 자식클래스();
        *
        * [동적 바인딩]
        * 컴파일 시 ; 부모 타입의 멤버만 접근 가능
        * 실행(runtime) 시 ; 오버라이딩 된 자식 메소드가 실행 됨
        * 자식 고유 멤버 사용 시 다운캐스팅 필요
        * */
        // 업 캐스팅 - 자식 객체의 참조값을 부모 타입 변수에 저장
        // 실제 객체는 Rabbit 이지만 Animal 시선으로 바라본다.
        Animal animal1 = new Rabbit();
        Animal animal2 = new Tiger();

        Zookeeper zookeeper1 = new Zookeeper();
        zookeeper1.feed(animal1);
        zookeeper1.feed(animal2);

        /* 동적 바인딩 : 컴파일 시점에는 부모의 메소드를 가리키고 있다가 실행 시점(런타임) 때 참조 변수가 실제로 가리키는 객체로 연결됨
        오버라이딩 된 메소드가 실행되는 원리이다. */
        animal1.cry();
        animal2.cry();

//        animal1.jump();   // 부모 타입에는 jump 가 없기에 컴파일 에러 발생. 부모 타입으로는 자식만의 고유 기능 접근 불가

        ((Rabbit) animal1).jump();  // 다운 캐스팅 : 명시적 형변환이 필요.
//        ((Rabbit) animal2).jump();  // ClassCastException : 형변환 에러 발생. animal2 의 실제 객체는 Tiger 이기에 잘못된 다운 캐스팅

        // 다운캐스팅 전에 instanceof 연산자로 가리키는 객체를 확인하는 것이 안전
        System.out.println("animal1 은 Tiger 타입인가? " + (animal1 instanceof Tiger));

        System.out.println();

        /* 다형성을 활용한 객체 배열 */
        Animal[] animals = new Animal[5];
        animals[0] = new Rabbit();
        animals[1] = new Tiger();
        animals[2] = new Rabbit();
        animals[3] = new Tiger();
        animals[4] = new Rabbit();

        for(Animal a : animals) {
            a.cry();

            if(a instanceof Rabbit) {
                ((Rabbit)a).jump();
            } else if(a instanceof Tiger) {
                ((Tiger)a).bite();
            }
        }

        System.out.println();
        Zookeeper zookeeper2 = new Zookeeper();
        for(Animal animal : animals) {
            zookeeper2.feed(animal);
        }
    }
}
```

## 추상 클래스

직접 객체를 생성할 수 없으며, 자식 클래스의 공통 기능을 정의하는 부모 클래스

- abstract 키워드로 선언
- 일반 메소드와 추상 메소드를 모두 가질 수 있다.
- 추상 메소드는 몸체가 없으며 자식 클래스에서 반드시 오버라이딩 해야한다.
- 참조변수 타입으로 사용할 수 있다 - 다형성 적용 가능

```java
package com.ohgiraffers.section02.abstactclass;

public abstract class Player {
    /*
    [추상 클래스]
     - abstract 키워드로 선언
     - 일반 메소드와 추상 메소드를 모두 가질 수 있다.
     - 추상 메소드는 몸체가 없으며 자식 클래스에서 반드시 오버라이딩 해야한다.
     - 참조변수 타입으로 사용할 수 있다 - 다형성 적용 가능
     */

    // 몸체가 없는 추상 메소드
    public abstract void attack();

    // 일반 메소드
    public void levelUp() {
        System.out.println("레벨업!!");
    }
}
```

추상 메소드가 들어간다면 무조건 추상 클래스가 되어야 한다.

반드시 필요한 기능을 추상 메소드로 만들어 강제한다.

## 인터페이스

클래스가 반드시 구현해야 할 기능의 규칙을 정의한다.

- 인터페이스 안에는 추상 메소드만 작성 가능하다.
- 인터페이스의 추상 메서드에는 public abstract 가 자동으로 적용된다.
- 인터페이스를 구현할 때는 extends 대신 implements 를 사용한다.

```java
public interface IConnectable {

    /* [인터페이스]
    * 클래스가 반드시 구현해야 할 기능의 규칙을 정의한다.
    *
    * - interface 키워드로 선언
    * - 직접 객체를 생성할 수 없음
    * - 클래스는 implements 로 인터페이스를 구현
    * - 구현 클래스는 추상 메소드를 반드시 오버라이딩 해야함
    * - 인터페이스 타입으로 구현 객체를 참조할 수 있음 (다형성)
    * - 여러 인터페이스를 동시에 구현할 수 있음
    * */

    // 일반 메소드 작성 불가
    // public void connect() {}

    public abstract void connect();

    // 인터페이스 추상 메서드에는 자동으로 public abstract 가 적용되어 생략 가능하다
    void disconnect();
}
```

```java
public class Keyboard implements IConnectable{

    @Override
    public void connect() {
        System.out.println("키보드가 usb 포트에 연결 되었습니다.");
    }

    @Override
    public void disconnect() {
        System.out.println("키보드 연결을 해제합니다.");
    }
}
```

```java
public class Computer {

    public void connectDevice(IConnectable device) {
        System.out.println("컴퓨터의 usb 포트에 장치를 연결합니다.");
        device.connect();
    }

    public void disconnectDevice(IConnectable device) {
        System.out.println("컴퓨터에서 장치 연결을 해제합니다.");
        device.disconnect();
    }
}
```

## 추상클래스와 인터페이스 차이
| 추상 클래스 | 인터페이스 |
| --- | --- |
| abstract class | interface |
| extends | implements |
| 직접 객체 생성 불가 |  |
| 인스턴스 필드 O | 인스턴스 필드 X |
| 부모 클래스 하나만 상속 | 여러 인터페이스 구현 가능 |
| 공통 상태와 기반 구현을 가진 계층에 사용 | 여러 클래스가 지킬 기능 / 규격 / 역할 선언 |
| 공통 속성과 기능을 물려주는 미완성 부모 클래스 | 구현 클래스가 지켜야 할 기능의 약속 |
